# autopilot — 頼まれたことを最後までやり切り、繰り返す仕事は自動にする

ユーザーの方針: 「いちいちお願いするのが面倒なので、全部自動にしたい」（2026-10-28）。
一度頼まれたことは、次から頼まれなくても回るようにするのがこのスキルの目的。

## 1. 依頼を受けたら（毎回の流れ）

途中で「次はこれをしますか？」と聞かずに、下の順で最後まで進める。止まるのは「3. 必ず止まって聞くこと」に当たるときだけ。

1. **前の経緯を確かめる**: 関係する NotebookLM のノートブックがあれば `~/.local/bin/nlm notebook query <ID> "決定事項と未対応" --timeout 180`（ID は `~/.claude/CLAUDE.md` の表）。クラウドで nlm が使えないときは、リポジトリの `docs/` の最新の作業記録を読む
2. **文章の作業は ds に任せる**: 要約・下書き・翻訳・エラーの要約は `~/.local/bin/ds`（`dscommit`・`dserr`）。渡してはいけないもの（`10_Life`・秘密情報・利用者や第三者の個人情報・仕事の資料）は渡さない。入力は1回 10KB くらいまでに分けて送る（大きいと無料枠の上限に当たり、遅い Mac 内の AI に回って返ってこなくなる）。3分返ってこなければ止めて Claude が行う
3. **作る・直す**: Claude が編集する
4. **確かめる**: ビルド・テスト・lint を実行する。サイトなら公開後に本番 URL が 200 か見る（`site-checker` 担当に任せてよい）。データベースの変更の前後は `db-guardian`、コミットの前の大きい変更は `code-reviewer`
5. **残す**: 「2. もう OK をもらっていること」の範囲でコミット・push・公開まで行う
6. **記録する**: まとまった作業なら `docs/YYYY-MM-DD_作業記録.md` を書く（下書きは ds）。nlm が使えれば該当ノートブックに `nlm source add <ID> --file <パス> --title "<日付> 作業記録" --wait`
7. **報告する**: 日本語で、何が変わったか・確かめた結果・残っていることを短く

待ちがあっても返事を終えない（Monitor で待つ／先に進められる部分をやる）。

## 2. もう OK をもらっていること（聞かずに進めてよい）

| 対象 | してよいこと | いつから |
|---|---|---|
| DTM PICKS のガイド記事 | 条件（【要確認】なし・全事実に出典・ビルド成功）を満たせば本番公開 | 2026-10-26 |
| DTM DIGS のアーティスト | 公式情報で確認できたものを本番公開 | 2026-10-27 |
| X の紹介投稿 | URL なしの紹介文をキューに入れる。1日1本まで | 2026-10-27 |
| ローカルのコミット | 自分が変えたファイルだけをコミットする | — |

この表にない「外に出る操作」（push・公開・投稿・送信・設定変更）は、**1回目だけ**ユーザーに聞く。そのとき「次からも聞かずにやってよいですか？」も一緒に聞き、OK ならこの表に1行足して、メモリにも残す。こうして聞く回数を減らしていく。

## 3. 必ず止まって聞くこと（自動にしない）

- ログイン・認証コード・パスワード・API キーやトークンの入力（ユーザーが自分で行う。Claude は入力しない）
- お金がかかること（購入・有料プラン・X の URL 入り投稿や1日2本以上など、費用が増える変更）
- 消すこと（ファイル・データベースの行・メール・リポジトリ・ノートブック）
- 新しい公開アカウントを作ること、他人へのメッセージやメールの送信
- `10_Life` の中身を GitHub や外部の AI に出すこと

## 4. 繰り返しになりそうな依頼は、自動にする

次のどれかに当たったら、作業を終えたあとに定期実行として登録する。

- 「毎日」「毎週」「定期的に」「いつも」「自動で」「〜しといて」と言われた
- 同じ種類の依頼が2回目になった（例: 「コミットして push して」「動作確認して」）

登録のしかた:

1. 何を・いつ・どこまで自動で（公開まで？下書きまで？）を1行でまとめる。はっきりしない点だけユーザーに聞く
2. 登録先を選ぶ
   - **クラウドの定期実行（ルーティン）**: GitHub のリポジトリだけで完結するもの。Mac を閉じていても動くので、こちらを優先する（`/schedule`）
   - **Mac の定期タスク**: `10_Life` を読むもの、Mac の中のファイル（`~/Movies` など）が要るもの
   - **GitHub Actions**: Claude を使わない決まった処理（X の投稿など）
3. タスクの説明には、このスキルの「1」「3」を守ることと、渡してはいけないもの、`2.` の表の範囲を書く
4. 最初の1回は手動で動かして結果を確かめる
5. ユーザーに、登録した内容（名前・時刻・どこまで自動か）を報告する

## 5. いま動いている自動の仕事

定期タスクの一覧は `mcp__scheduled-tasks__list_scheduled_tasks`（Mac）と `/schedule list`（クラウド）で確かめる。クラウドへの移行の計画と進み具合は `docs/2026-10-28_クラウド移行計画.md`。
新しく足すときは、同じことをするタスクがないか先に確かめる（二重に動かさない）。

毎晩 23:50 の `lifeos-daily-checkup` が、自動の仕事が動いたかを点検して NotebookLM「LifeOS 作業記録」（ID: fb4e7643-59ee-41bf-82fa-30628eb4310f）にメモを残す。日曜は1週間のまとめも作る。新しい定期実行を足したら、点検の対象に入るか（Mac の定期タスクなら自動で入る。クラウドや GitHub Actions なら点検の手順に足す）を確かめる。
