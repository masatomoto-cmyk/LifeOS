  > 画像の削除が失敗した場合は、アカウント削除を止めて再試行できますか？DBだけ消えて画像が残るケースも確認対象か気になりました。

## 返信（案）

@umitdogan さん、コメントありがとうございます。鋭いご指摘で、確認したところ今の実装では対応できていませんでした。

- **画像の削除に失敗しても、アカウント削除は止まりません。** Edge Function で `storage.from('avatars').list()` / `remove()` の戻り値（error）を見ていないため、失敗してもそのまま `auth.admin.deleteUser()` に進みます。つまり「DB は消えたのにアイコン画像だけ残る」ケースは起こりえます。avatars は公開バケットなので、URL を知っていれば画像を見られる状態になります。
- **記事のテストも DB だけが対象でした。** ロールバックする DO ブロックで確かめたのは SQL 側の連鎖削除までで、Storage の削除失敗は確認対象に入っていませんでした。

直すとしたら、次の形にする予定です。

1. 画像の `list` / `remove` のどちらかでエラーが出たら 500 を返し、アカウント削除（`deleteUser`）に進まない
2. 画面には「削除に失敗しました。もう一度お試しください」と出し、同じボタンで再試行できるようにする
3. 再試行しても問題ないよう、各手順は何度実行しても同じ結果になる形にする（コメント・通知の掃除や画像の削除は、すでに消えていれば何もしないだけ）

修正とテストができたら、記事にも追記します。気づかせていただきありがとうございました。
