# 2026-10-29 作業記録: Roland S-1 を Claude が操作できるようにした

## 概要
- 日付: 2026‑10‑29  
- 題: Roland S‑1 を Claude が操作できるようにした  
- 使用した素材: `S1.zip`（README, s1‑controls.pdf, Roland S‑1 Control 2.10.8 インストーラ）  
- プラグイン: Logic Pro 専用 AU（MIDI FX、内部は Cabbage/Csound）  

## やったこと
- `bin/s1ctl.py` と `bin/s1`（`~/.local/bin/s1` へシンボリックリンク）を作成  
- Python 仮想環境 `~/.venvs/s1` を構築し `mido, python-rtmidi, numpy, pypdf` をインストール  
- CC 対応表を Roland 公式マニュアル v1.02 の Control change list と照合し一致させた  
- 環境変数 `S1_CHANNEL`（デフォルト 12）で受信チャンネルを設定可能にした  

## 使い方
```bash
s1 list                         # 操作できるパラメータの一覧
s1 set cutoff=40 reso=90        # パラメータ設定
s1 cc 74 40                     # 任意 CC 送信
s1 note C4                      # 単音ノート送信
s1 play "C4 E4 G4" --dur 0.25   # フレーズ演奏
s1 chord "C4 E4 G4" --dur 1    # 和音（Poly モードで）
s1 pc 3                         # パターン切り替え（0 始まり）
s1 bend 4000                    # ピッチベンド（-8192〜8191、0=中央）
s1 panic                        # 全音符オフ
s1 test                         # USB 音声録音し音量・音程測定
```  

## わかったこと・つまずき
- 初期はチャンネル 1 に送信していたが S‑1 本体はチャンネル 12 受信していた  
- シーケンサーが常に鳴り続き、MIDI 変化が埋もれたため 16 チャンネルを順にテストし 12 を特定  
- `cutoff` を 10・60・127 にすると、音の明るさ（周波数の重心）が 276・1652・2707 Hz に変化（つまみが効いている）
- `RANGE` (CC14) は 0〜5 で 1 段ごとに 1 オクターブ、標準は 3（8'）  
- AIRA Link は Off、Identity Request に対して本体は応答しない  
- 本体のつまみや鍵盤操作は USB MIDI で送信されない（送信側は未確認）

## プラグインが送っているもの（2026-10-29 夕方）

### 調べ方
- 仮の MIDI 出口「S-1 Spy」を `bin/midispy.py` で作り、Logic の S-1 トラック（External Instrument、チャンネル 12）の MIDI Destination を一時的に S-1 Spy にして記録した。S-1 には何も届かない状態で試した

### 分かったこと
- S-1 Control が動いている間は、ピッチベンド 0（チャンネル 12）が**毎秒約 1500 件**、休みなく送られる。46 秒で約 7 万件
- 画面を閉じても止まらない。バイパスすると 0 件、バイパスを外すとすぐ毎秒約 1500 件に戻る
- 全メッセージが重複して届く（ノートオン・ノートオフが 2 回ずつ、ピッチベンドは同時刻に 4 件）
- つまみの CC（3, 13, 19, 21, 23）は動かした分だけ送られる。画面を開いたときに保存値をまとめて送る動きはなかった → 「前回の値をまとめて送って音色を壊す」という仮説は外れ
- 新しい仮説（未確認）: 大量のピッチベンドで S-1 の MIDI 受信があふれ、ノートオフが抜けて鳴りっぱなしになったり、受信が固まって無音になったりした
- 新しい MIDI 出口ができると、Logic は Mackie Control の確認用 SysEx（00 00 66 …）を 16 件送る。Roland 用ではないので S-1 にはたぶん無害
- Logic の知らせで、P-6 用の音源も S-1 の MIDI 入口に送る設定だと分かった。「P-6 12」トラックは S-1 と同じチャンネル 12（未確認）

### 対応・次にやること
- S-1 Control はバイパスのままにした。送り先は S-1 に戻した（ユーザーが操作）。`s1 test` で鳴ることを確認
- S-1 Control は使うときだけバイパスを外す。ふだんは `s1` コマンドを使う
- ピッチベンドの連続送信を設定で止められるか、作者に報告できるかを確認する
- P-6 トラックの送り先を P-6 用に直すか確認する

## 追記（夕方）: Scripter でピッチベンドを捨てる
- S-1 トラックの MIDI FX で、S-1 Control の後ろに Scripter を挿した。スクリプトは `function HandleMIDI(e){ if (e instanceof PitchBend) return; e.send(); }`
- midispy で確認: Scripter を止めると数秒でピッチベンド約6,200件、戻すと 0 件。CC（74 など）は通る。重複もなくなり1回ずつ届く
- Logic は再生していない間、このトラックの MIDI FX の出力を止める。つまみの CC はたまり、再生した瞬間に最後の値だけまとめて送られる → つまみを動かしたあと再生を一瞬して送る
- S-1 Control の数字欄はダブルクリックで入力できない。縦ドラッグは 1px ≒ 0.63
- 太いベースの値（SAW127 SUB80 RANGE3 FREQ40 RESO30 ENV60 ADSR 0/50/40/20）にして S-1 に送った
- ところが録音が無音と同じ -49dB のまま。s1 コマンドで直接 cutoff を変えても同じ → S-1 が鳴っていない（作業を始めた時点から）。本体の鍵盤・音量・電源の入れ直しの確認待ち
- 録音用スクリプト: C2 を鳴らしながら3秒録音し、全体・2kHz以上・200Hz以下の RMS を測る
- 追記2: -49dB の正体は「無音」ではなく S-1 の鳴りっぱなし（65.9Hz=C2 と 1975Hz=B6。トラックのリージョンにある note 36・95）。USB 録音自体は正常（本体の鍵盤の音は入り、無音は -inf）
- 電源を入れ直した直後は正常（s1 で鳴らすと -65dB）。S-1 Control の値を送るため Logic を一瞬再生したら、また鳴りっぱなしになった → **Logic の再生で S-1 が壊れる**。s1 panic・停止の合図・ノートオフの連打でも止まらず、発音モードの切り替え（CC80）で -48 → -60dB まで下がっただけ
- 次は再生を使わずに送る方法を試す（トラックの録音待機など）
- 追記3: 再生を使わずに送る方法として、IAC から CC64=0 を1つ入れて Logic を起こすと、たまった CC が流れた（FREQ127 で -57 → -45dB）。ただし、そのあとまた鳴りっぱなしになった
- 電源を入れ直した直後に s1 だけで3回鳴らすと、毎回無音（約 -91dB）に戻った → s1 だけなら壊れない。きっかけは Logic 側
- Logic は同じメッセージを2重に送る（CC64=0 が2回、note_on も2回）。原因は未調査
- 根本原因の洗い出しは次のチャットに引き継いだ: docs/2026-10-29_引き継ぎ_S-1鳴りっぱなしの根本原因.md

## 追記4（17時ごろ）: 鳴りっぱなしの根本原因が分かり、直した
- **根本原因: MIDI のループ。** S-1 は受け取ったノートを MIDI OUT から送り返す（ソフトスルー。velocity 1 でも返す。CC は返さない）。Logic のトラック 14 の「MIDI入力」が「すべて」だったので、返ってきたノートが Logic に入り、S-1 トラックからまた S-1 へ送られていた。しかも S-1 Control が入力を2回流すので、1周ごとにノートが倍になり、S-1 が固まった
  - 前の「送り返さない」という結論は、確かめ方の誤り（ほかの条件は同じで、今回は確実に返ってくるのを確認した）
- 調べ方: midispy の記録を16進でも残すよう直し、`bin/midireplay.py` で Logic を通さずに S-1 へ再生。Logic が起動時に送る RPN 3/4（CC100/101/6 の27組）と Mackie の sysex は、再生しても壊れなかった。Spy の記録に、s1 で鳴らした C2 が2重で現れたことからループに気づいた
- 2重送信の原因: S-1 Control（バイパスすると1回になる）
- 対策
  1. トラック 14 の MIDI入力を「IAC ドライバ」にした（S-1 から返るノートが入らない。IAC で起こす方法は使える）
  2. Scripter を、ピッチベンドを捨て、3ms 以内の同じ命令を1つにするスクリプトに替えた
  3. プロジェクトを保存した
- 確認（送り先 S-1）: IAC で起こして s1 で鳴らす ×2、Logic を0.5秒再生 → どれも鳴ったあと無音（-inf）に戻った
- 音色: SAW127 SUB80 RANGE3 RESO30 ENV60 ADSR 0/50/40/20 で、FREQ を変えて測った（全体 / 2kHz以上）
  - FREQ 0: -85dB / -119dB
  - FREQ 40（太いベース・最終）: -62.5dB / -104dB
  - FREQ 127: -61dB / -80dB
- 注意: S-1 の鍵盤で弾いた音を Logic に録音したいときは、MIDI入力を「S-1」に戻す必要がある。そのときは送り先を別にするか、External Instrument の出力を止めないとループする
- 新しい道具: `bin/midireplay.py`、`bin/s1measure.sh`、`bin/s1silence.sh`（midispy.py は16進も記録）

## 追記5: ループ対策を Logic 全体に広げた
- S-1 本体のメニューに「thru（MIDI Thru）」がある（MIDI IN 端子 → MIDI OUT 端子）。マニュアル: https://static.roland.com/manuals/s-1_manual_v102/jpn/55574729.html
  - 確認時点でも USB で送り返していた（thru を切り替えたかは未確認。USB に効くかも不明。thru OFF でも送り返すという利用者の報告あり: https://backstage.polyend.com/t/tracker-and-roland-s1-midi-loop-problem/12104 ）
- 送り返すのは受信チャンネル 12 のノートだけ（ch1・11・15 は返さない）→ 危ないのは ch12 で S-1 に送るトラック（S-1・P-6 12）
- Logic の 設定 → MIDI → 入力 で「S-1 MIDI OUT」のチェックを外した（Logic 全体で S-1 からの入力を受けない）。どのトラックを選んでもループしない
- トラック 14 の MIDI入力を「すべて」に戻した（MPK mini も使える）。確認: 送り先 Spy で s1 で鳴らす → Logic に入らない（0行）、IAC からの音は1回ずつ届く。送り先 S-1 で s1 で2回鳴らす・Logic を0.5秒再生 → どれも無音（-inf）に戻った。プロジェクトを保存
- S-1 の鍵盤を Logic に録音したいときは、この入力のチェックを一時的に戻す必要がある（そのときは送り先を S-1 以外にする）
