# 引き継ぎ：S-1 が鳴りっぱなし・無反応になる根本原因を洗い出す（2026-10-29 夕方）

## やってほしいこと
Logic Pro から Roland S-1 を使うと、S-1 が**鳴りっぱなしになり、新しい音にも反応しなくなる**。直るのは電源の入れ直しだけ。
この**根本原因を特定**してほしい。対症療法（Scripter で捨てる、など）より先に、「どのメッセージ（またはどの状況）が S-1 を壊すのか」を突き止めること。
原因が分かったら、防ぐ仕掛けを入れたうえで、S-1 Control で「太いベース」の音色にし、録音で確かめる。

## 今の環境と状態（2026-10-29 16:30 ごろ）
- S-1 は USB で Mac に接続。MIDI の送り先は `S-1 MIDI IN`、受信チャンネル 12（mido では channel=11）
- Logic「claude project」トラック 14「S-1」
  - 音源：External Instrument。**MIDI Destination は今「S-1 Spy」**（S-1 には何も届かない状態にしてある。Spy の記録プログラムは止めたので、送り先は実質どこにもない）
  - MIDI FX：① Roland S-1 Control（有効）→ ② Scripter（今日追加、有効）
  - Scripter の中身：`function HandleMIDI(e){ if (e instanceof PitchBend) return; e.send(); }`
- S-1 Control の画面の値：SAW127 SUB80 RANGE3 FREQ**127** RESO30 ENV60 ADSR 0/50/40/20（目標は FREQ 40）
- S-1 は電源を入れ直したばかりで正常（s1 で鳴らすと -57dB、止めると約 -91dB）
- 道具
  - `~/.local/bin/s1`（本体 `bin/s1ctl.py`、Python は `~/.venvs/s1`）
  - `bin/midispy.py 記録.log`：仮の出口「S-1 Spy」を作り、届いた MIDI を時刻つきで記録
  - 録音：`ffmpeg -f avfoundation -i ":1"`（`:1` = S-1）。無音は `-inf`
  - 測定スクリプト：C2 を 2.3 秒鳴らしながら 3 秒録音し、全体・2kHz 以上・200Hz 以下の RMS を出す（今日は scratchpad に置いた。次は `bin/` に置き直すとよい。中身は下の「付録」）

## 分かっている事実（今日すべて実測）
1. **S-1 Control は動いている間、ピッチベンド 0 を毎秒約1500件送る。** Scripter で止まる（止めると数秒で約6,200件、入れると 0 件）。CC は通る
2. **Logic は停止中、このトラックの MIDI FX の出力を止める。** つまみの CC はたまり、次のどちらかで処理が動いた瞬間に、最後の値だけまとめて出る
   - Logic の再生
   - 外からの MIDI 入力（IAC バスから CC64=0 を1つ入れる）
3. **Logic は同じメッセージを2重に送る。**
   - IAC から入れた CC64=0 は2回届いた
   - 再生時の note_on も2回ずつ届いた（例：note 36 vel80 が8回、note_off 36 が14回）。なぜ2重になるかは未調査
4. Logic は停止のとき、全チャンネルにピッチベンド 0・アフタータッチ 0・CC1/2/4/64=0 を送る
5. Logic は新しい MIDI の出口ができるたびに sysex `F0 00 00 66 …`（Mackie Control の挨拶）を送る（midispy 起動時に毎回届く）。S-1 の電源を入れ直したときも、S-1 MIDI IN に送っている可能性が高い（未確認）
6. **鳴りっぱなしは今日3回起きた**
   - ① 作業を始めた時点ですでに（65.9Hz=C2 と 1975Hz=B6 が鳴り続ける。トラックのリージョンにある note 36・95）
   - ② 電源を入れ直したあと、Logic を 0.5 秒再生して S-1 Control の値を送ったあと
   - ③ 電源を入れ直したあと、IAC で Logic を起こして FREQ127 を送り、そのあと s1 で C2 を鳴らしたあと（C2 が残る、-56dB）
7. 鳴りっぱなしの間は新しい音も出ない。次は効かない
   - s1 panic（全チャンネル・全128音のノートオフ）
   - MIDI Stop
   - ノートオフの連打（note_off と velocity 0 の note_on）
   - CC64=0
   - ampmode=0
   発音モード（CC80）を切り替えると、-48 → -60dB に下がっただけ。直るのは電源の入れ直しだけ（今日3回）
8. **s1 だけなら壊れない**：電源を入れ直した直後、Logic の送り先を Spy にした状態で s1 で C2 を3回鳴らした → 毎回 -57dB で鳴り、そのあと約 -91dB に戻った
9. S-1 は受け取った MIDI を MIDI OUT から送り返さない（MIDI のループではない）
10. USB の録音は正常（本体の鍵盤の音は入る）
11. つまみが効く証拠：入れ直した直後は -57dB（高音 -92dB）、IAC で FREQ127 を送ったあとは -45dB（高音 -65dB）
12. S-1 Control の数字欄は直接入力できない。縦ドラッグは 1px ≒ 0.63。つまみの操作には全画面操作の許可が要る（プラグインの画面は別のプロセスが描いているため）

## 根本原因の候補
- (A) **2重に届くノート**：S-1 が同じ音の note_on を2回受けると、発音の数え方が狂い、ノートオフで止まらなくなる
- (B) **Logic が起動・停止のときに送る初期化メッセージ**：アフタータッチ・CC2/4・全チャンネルのピッチベンドなど
- (C) **Logic が送る sysex**：Mackie の挨拶など。S-1 の電源を入れ直したときや、ポートの数が変わったときに送っている可能性
- (D) **S-1 Control が出す、ピッチベンド以外のもの**：起動時に何か送っている、など
- (E) **短い時間に大量のメッセージ**：S-1 の受信が詰まる（ピッチベンドの洪水は Scripter で止めたが、2重送信のぶん量は増える）
- (F) S-1 本体側の不具合：特定の順番のメッセージで固まる。ファームウェアの版も確かめる

## 確かめ方（再生 → 二分探索）
考え方：**Logic が実際に送ったものをそのまま記録し、Logic を通さずに S-1 へ再生して再現させる。** 再現したら、メッセージの列を半分ずつに分けて、犯人を1つに絞る。

1. **記録**
   - midispy を起動し、トラックの送り先を S-1 Spy のままにする
   - ②（0.5 秒の再生）と ③（IAC で起こす + つまみ）を Logic で行い、届いたものをすべて記録する
   - 時刻・バイトをそのまま残すため、記録を mido のメッセージとして読み戻せる形（例：`msg.hex()`）で保存するよう midispy を少し直す
2. **再生用スクリプトを作る**：記録ファイルを読み、同じ間隔で `S-1 MIDI IN` に送る（`bin/midireplay.py` など）
3. **再現の確認**
   - S-1 の電源を入れ直す → 無音（-inf）を確かめる
   - 記録を再生 → s1 で C2 を鳴らす → 無音に戻るかを測る
   - 再現しないなら、Logic を通したときだけ起きる何か（タイミング、ポートの開き方、sysex）が疑わしい → (C) を先に調べる
4. **二分探索**：再現した記録を種類ごと（ノート・CC・アフタータッチ・ピッチベンド・sysex）に分けて1種類ずつ再生する。再現した種類をさらに半分ずつに分ける。**1回ごとに電源の入れ直しと無音の確認が必要**なので、ユーザーに頼む回数を減らすよう、1回で確かめられることを増やす
5. **2重送信の原因**：Logic の設定（トラックの「MIDI入力」が「すべて」になっている、録音待機のトラックが複数ある、IAC やコントロールサーフェスの設定など）を調べ、1回だけ届くようにして ② ③ が起きるか確かめる
6. **sysex**：Logic の「コントロールサーフェス」の設定で S-1 が出力先に選ばれていないか確かめる。電源を入れ直したときに S-1 MIDI IN へ何が送られるかは、Mac 側のポートを直接は横取りできないので、Logic のコントロールサーフェスを一時的に切って、② ③ が起きるかで判断する

## 進め方の注意
- S-1 に何かを送ったら、**必ず無音を測る**（`-inf` か約 -90dB 以下なら正常。-60〜-48dB が続いたら鳴りっぱなし）
- 鳴りっぱなしになったら、全音停止などは効かない。すぐユーザーに電源の入れ直しを頼む。入れ直すと Logic が「ポートの数が変わった」という知らせを出す → 「続ける」で閉じる（背景操作の app_click でできる）
- 全画面操作は、頼む前に「画面に許可の確認が出るので見ていて」と伝える
- Logic の再生は、原因が分かるまで S-1 に向けて行わない
- `ampmode=127` は送らない。S-1 を OMNI（全チャンネル受信）にしない
- 鳴らしたら最後に `s1 panic`

## 原因が分かったあと
1. 防ぐ仕掛けを入れる（Scripter で捨てる、Logic の設定を直す、など）。そのうえで ② ③ の操作をしても壊れないことを、無音の測定で確かめる
2. トラックの送り先を S-1 に戻す
3. S-1 Control で FREQ を 40 に戻し、太いベース（SAW127 SUB80 RANGE3 FREQ40 RESO30 ENV60 ADSR 0/50/40/20）を送る
4. FREQ 0・40・127 で録音して、音が変わることを数字で示す。最後に無音を確かめる
5. 作業記録を書き、NotebookLM「Roland S-1・DTM 機材 作業記録」（ID: f723ade5-96e0-4f74-8a18-e33220eac600）に追加する
- 音色を本体に保存するには、本体の WRITE ボタンを押す（ユーザーが行う）

## 付録：測定スクリプト
```bash
#!/bin/bash
# 使い方: measure.sh 名前  … S-1 で C2 を鳴らしながら3秒録音し、音量を測る
D=保存先フォルダ
W="$D/$1.wav"; rm -f "$W"
ffmpeg -loglevel error -f avfoundation -i ":1" -t 3 -ac 1 "$W" &
P=$!; sleep 0.4
~/.local/bin/s1 play --dur 2.3 "C2" >/dev/null 2>&1
wait $P; ~/.local/bin/s1 panic >/dev/null 2>&1
rms() { ffmpeg -hide_banner -i "$W" -af "$1astats=measure_overall=RMS_level:measure_perchannel=none" -f null - 2>&1 | awk '/RMS level/{print $NF}' | tail -1; }
echo "$1: 全体 $(rms '') dB / 2kHz以上 $(rms 'highpass=f=2000,') dB / 200Hz以下 $(rms 'lowpass=f=200,') dB"
```
無音だけ測るとき：`ffmpeg -f avfoundation -i ":1" -t 1.5 -ac 1 s.wav` を録って、同じように `astats` の RMS を見る。
