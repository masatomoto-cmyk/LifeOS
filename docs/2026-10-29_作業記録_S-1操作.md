# 2026-10-29 作業記録: Roland S-1 を Claude が操作できるようにした

## 概要
- 日付: 2026‑10‑29  
- 題: Roland S‑1 を Claude が操作できるようにした  
- 使用した素材: `S1.zip`（README, s1‑controls.pdf, Roland S‑1 Control 2.10.8 インストーラ）  
- プラグイン: Logic Pro 専用 AU（MIDI FX、内部は Cabbage/Csound）  

## やったこと
- `bin/s1ctl.py` と `bin/s1`（`~/.local/bin/s1` へシンボリックリンク）を作成  
- Python 仮想環境 `~/.venvs/s1` を構築し `mido, python-rtmidi, numpy, pypdf` をインストール  
- CC 対応表を Roland 公式マニュアル v1.02 の Control change list と照合し一致させた  
- 環境変数 `S1_CHANNEL`（デフォルト 12）で受信チャンネルを設定可能にした  

## 使い方
```bash
s1 list                         # 操作できるパラメータの一覧
s1 set cutoff=40 reso=90        # パラメータ設定
s1 cc 74 40                     # 任意 CC 送信
s1 note C4                      # 単音ノート送信
s1 play "C4 E4 G4" --dur 0.25   # フレーズ演奏
s1 chord "C4 E4 G4" --dur 1    # 和音（Poly モードで）
s1 pc 3                         # パターン切り替え（0 始まり）
s1 bend 4000                    # ピッチベンド（-8192〜8191、0=中央）
s1 panic                        # 全音符オフ
s1 test                         # USB 音声録音し音量・音程測定
```  

## わかったこと・つまずき
- 初期はチャンネル 1 に送信していたが S‑1 本体はチャンネル 12 受信していた  
- シーケンサーが常に鳴り続き、MIDI 変化が埋もれたため 16 チャンネルを順にテストし 12 を特定  
- `cutoff` を 10・60・127 にすると、音の明るさ（周波数の重心）が 276・1652・2707 Hz に変化（つまみが効いている）
- `RANGE` (CC14) は 0〜5 で 1 段ごとに 1 オクターブ、標準は 3（8'）  
- AIRA Link は Off、Identity Request に対して本体は応答しない  
- 本体のつまみや鍵盤操作は USB MIDI で送信されない（送信側は未確認）

## 午後の続き（2026-10-29）

### 分かったこと
- 1回目の電源入れ直し後、無音時の USB 録音は完全な 0、ドミソで RMS -18dB。録音は直っていた（前回の録音不良は S-1 側の状態が原因だった可能性）
- Logic が「前のオーディオ装置が使えないので MacBook Air のスピーカーを使う」通知を出していた（S-1 の電源を切ったため）
- S-1 Control プラグイン画面は app_* の背景操作だと別プロセスのため拒否され、全画面操作ならドラッグできた
- プラグインで FREQ 0 → 録音 -65dB、FREQ 127 → -46dB。つまみで実際に音が変わることを確認
- その後 FREQ 76 にしたところで、録音が完全な 0 になり、本体からは低い音が鳴りっぱなしになった
- 全チャンネル・全 128 音のノートオフを直接送ると鳴りっぱなしは止まった → S-1 は CC123/120（全音停止）を無視する
- 止まった後も S-1 は Mac からの音も本体の鍵盤も無音。基本値（DRAW オフ、saw 127、cutoff 127、sustain 127 など）を送っても無音のまま。2回目の電源入れ直しで復帰
- 復帰後、s1 コマンドで cutoff 10 → -61dB、cutoff 127 → -51dB（2回とも同じ）。s1 だけなら壊れない

## プラグインが送っているもの（2026-10-29 夕方）

### 調べ方
- 仮の MIDI 出口「S-1 Spy」を `bin/midispy.py` で作り、Logic の S-1 トラック（External Instrument、チャンネル 12）の MIDI Destination を一時的に S-1 Spy にして記録した。S-1 には何も届かない状態で試した

### 分かったこと
- S-1 Control が動いている間は、ピッチベンド 0（チャンネル 12）が**毎秒約 1500 件**、休みなく送られる。46 秒で約 7 万件
- 画面を閉じても止まらない。バイパスすると 0 件、バイパスを外すとすぐ毎秒約 1500 件に戻る
- 全メッセージが重複して届く（ノートオン・ノートオフが 2 回ずつ、ピッチベンドは同時刻に 4 件）
- つまみの CC（3, 13, 19, 21, 23）は動かした分だけ送られる。画面を開いたときに保存値をまとめて送る動きはなかった → 「前回の値をまとめて送って音色を壊す」という仮説は外れ
- 新しい仮説（未確認）: 大量のピッチベンドで S-1 の MIDI 受信があふれ、ノートオフが抜けて鳴りっぱなしになったり、受信が固まって無音になったりした
- 新しい MIDI 出口ができると、Logic は Mackie Control の確認用 SysEx（00 00 66 …）を 16 件送る。Roland 用ではないので S-1 にはたぶん無害
- Logic の知らせで、P-6 用の音源も S-1 の MIDI 入口に送る設定だと分かった。「P-6 12」トラックは S-1 と同じチャンネル 12（未確認）

### 対応・次にやること
- S-1 Control はバイパスのままにした。送り先は S-1 に戻した（ユーザーが操作）。`s1 test` で鳴ることを確認
- S-1 Control は使うときだけバイパスを外す。ふだんは `s1` コマンドを使う
- ピッチベンドの連続送信を設定で止められるか、作者に報告できるかを確認する
- P-6 トラックの送り先を P-6 用に直すか確認する
