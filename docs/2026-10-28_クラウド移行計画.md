# LifeOS クラウド移行計画（2026-10-28）

目的: Mac を閉じていても、LifeOS の自動の仕事が全部動き、スマホからすべて確認・指示できるようにする。

| 種類 | もの | Mac に頼っている点 |

## 2. 移したあとの形

```
スマホ（Claude アプリ / claude.ai/code）
   │ 指示・結果の確認
   ▼
クラウドの Claude（定期実行＝ルーティン）── GitHub のリポジトリを編集して push
   │                                         │
   │ コネクタ（Googleカレンダー・Supabase・Vercel・Gmail）  ▼
   │                                     Vercel が push を見て自動で公開
GitHub Actions（Claude を使わない定期処理：X 投稿・リール投稿）
```

- **Claude の定期タスク** → Claude Code のクラウドの定期実行（ルーティン）に移す。スマホの Claude アプリで結果を見られる
- **公開** → DTM DIGS・DTM PICKS を Vercel と GitHub でつなぐ。「main に push したら自動で公開」の形にして、Mac の `npx vercel` をやめる
- **X 自動投稿** → GitHub Actions（GitHub が決まった時刻に処理を動かしてくれる機能）に移す。投稿キューは非公開リポジトリのファイルにする。X のキーは GitHub の Secrets（暗号化して保存する場所）に置く
- **ds** → クラウドでも動くように、Groq のキーをクラウドの環境変数に登録する。Ollama（Mac 内の AI）はクラウドでは使えないので、Groq だけで動かす
- **NotebookLM（nlm）** → Google のログイン情報（クッキー）が必要で、クラウドに置くと切れやすく危ない。クラウドのタスクから作業記録を残す部分は、「リポジトリの `docs/` に記録を書く」に置き換える（NotebookLM への追加は、手が空いたときにまとめて行う）
- **勤怠** → `10_Life` は GitHub に上げない。代わりに、スマホから直接 Google カレンダーに「出勤」「退勤」を記録する形にする（iPhone のショートカットか、Claude アプリに「出勤」と言うだけ）。カレンダーが元の記録になるので、毎晩の同期タスクはいらなくなる
- **`10_Life` などのファイル** → 今のまま iCloud（スマホの「ファイル」アプリで見られる）。GitHub には置かない
- **リール** → 動画をクラウドの置き場所（Google ドライブなど）に置く必要がある。まだ定期実行していないので最後に回す

## 3. 進め方（順番）

| 段階 | やること | 誰が |
|---|---|---|
| 1 | DTM DIGS・DTM PICKS を非公開の GitHub リポジトリにして push。`.env` やキーが入らないか先に確かめる | Claude（作成と push はユーザーの OK のあと） |
| 2 | Vercel で両サイトを GitHub とつなぎ、push で自動公開にする | Claude（Vercel コネクタ）。設定の変更なので OK のあと |
| 3 | クラウドの環境を用意し、キー（Groq・Qiita・X など）を登録する | **ユーザー**（キーの入力は Claude はしない） |
| 4 | 定期タスクを1つずつクラウドのルーティンに移す。最初は読むだけの「公開チェック」で試し、うまくいったら公開する系に広げる | Claude |
| 5 | 移したタスクは、Mac 側を止める（二重に動かないように） | Claude |
| 6 | X 自動投稿を GitHub Actions に移し、Mac の launchd を止める | Claude ＋ ユーザー（Secrets の登録） |
| 7 | 勤怠をカレンダー記録に切り替え、iPhone のショートカットを用意する | Claude が手順を書き、ユーザーが iPhone で設定 |
| 8 | リールの動画置き場を決めて移す | あとで相談 |

## 4. どうしてもユーザーにしかできないこと

- GitHub・Vercel・X・Instagram などへのログインや、認証コードの入力
- API キーやトークンの入力（クラウドの環境変数、GitHub の Secrets）
- 有料プランへの変更など、お金がかかる操作

## 5. 気をつけること

- クラウドの定期実行には回数の上限がある（数は契約プランによるので、移す前に確かめる）。そのため、毎日の重いタスク（DIGS の5組・PICKS の記事）を優先し、軽い確認は1つにまとめる
- 公開・投稿まで自動にしているタスクは、移した直後の数日は結果を毎回見る
- 移行が終わるまで、同じタスクが Mac とクラウドの両方で動かないようにする
